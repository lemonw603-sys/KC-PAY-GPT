## 1 首页：五个决定 + 今天要处理的

- 顶部一行五个决定，各一个控件，当前值直接可见：接不接单（接单并处理 / 接单但暂停处理 / 停止接单）、走哪条路线（API / Browser）、用哪个卡台（下拉，Browser 卡台）、能不能付钱（Browser 付款开关，需确认框）、能不能开卡补钱（合并开关）。改动即写库，无密码、无手打确认词；只有「能不能付钱」用普通确认框。
- 下面三块：需要处理的订单（状态为需人工的，点进详情）；内部提醒（可关闭）；开工检查（一行一项，不通过的项给「去处理」跳转）。
- 移除：订单状态分布图、卡密与退款分布、最近订单列表（订单页已有）。
- 数据源：`/overview`、`/operations/readiness`、`/alerts`、`/operations/*`、`/provider-routes`、`/card-sources/browser/current`。付款开关与开卡补钱开关目前没有正式接口：需要新增两个 POST（写 `browser_payment_writes_enabled` 与合并后的 `supply_automation_enabled`）。

## 2 订单：一张表 + 一个抽屉

- 列表列：单号、产品、当前阶段（按 CORE_SPEC §1 阶段名）、需要我做什么（原因一句话）、卡尾号、身份、创建时间。筛选：需要处理 / 进行中 / 已完成 / 全部 + 搜索。
- 抽屉分区：执行时间线（已实现，读 `browser_run_events`）→ 资金与结果（attempt/账本/许可/PAYMENT_SUBMIT/对账结论）→ 客户与会话（重贴记录、打回原因）→ 动作区：取消并释放卡、人工付款已完成、确认 20X 已升级、同步卡交易、关闭对账案例。
- 删除：标签、备注、补发 CDK、灰度许可/撤销、退款观察列。
- 异常队列并入「需要处理」筛选；资金证据核对案例并入抽屉「资金与结果」，跨单队列留在诊断页。

## 3 CDK：生成与批次

- 保持现状：生成（产品下拉）、最近批次、下载 TXT、状态清单 CSV、作废。移除「交付记录」。
- 新增一列：批次内「已绑定 / 已退回 / 已作废」计数（来自新的退回事件）。

## 4 卡片：库存、卡台、导入、补钱

- 上半：卡片概况（可分配 / 使用中 / 暂不可用 / 永久停用）+ 两个设置（每卡成功次数、最低所需卡余额）。
- 中：卡台管理（当前 Browser 卡台、切换、新增备用卡台）+ 导入备用卡（预览 → 提交，已免密免手打）。
- 下：卡片列表（尾号、来源、余额、状态、当前订单、覆盖项）；开卡任务（人工）；卡余额充值队列（人工核实）折叠；补卡记录、新卡接管记录折叠。
- 删除：提醒阈值、每日自动补卡上限（已隐藏的死控件）。

## 5 诊断：低频、只读为主

- Browser 控制面：run 列表与检查点、派发队列与租约、人工接管/冻结/确认未知（现有 `/browser/runs`、`/browser/dispatch-jobs`、`/browser/runs/:id/control`）；账单地址设置。
- 资金证据核对队列（跨单）与三方对账案例。
- CSV 导出、开工检查原始项、Worker 心跳。
