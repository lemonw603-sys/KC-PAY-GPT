# 订单页结构 Demo v2 验收

## 范围

这是 D-349 确认后的订单页结构 Demo，仅合成数据，不连接生产、不调用订单/CDK接口、不生成卡密、不触发充值。

入口：`http://127.0.0.1:8899/step6-orders-structure-v2.html`

文件：`docs/design/prototypes/step6-orders-structure-v2.html`

依据：D-345～D-349；正式 CDK 页面/`cdks.js`/`cdk-service.js`；订单状态投影 `v1/src/services/order-stage.js`；生产只读订单字段覆盖核对。

## 已核对业务场景

- 默认显示最近客户充值，邮箱作为主识别信息。
- 同一个 CDK 的最新记录作为主行，历史失败在主行下方展开；演示中 `lin@example.test` 的“付款前失败”展开正常。
- CDK 已兑换与充值成功分开显示；成功、处理中、需要补资料、付款结果待核实、失败可重提分别展示。
- 提交时间与充值成功时间分列；未成功时成功时间显示“—”。
- API/Browser、卡台、卡尾号分开显示；未分配卡显示“待分配”。
- 付款结果待核实详情明确提示“不可重复充值”。
- 详情显示对应完整测试 CDK、复制入口、阶段摘要、历史记录和“在 CDK 页定位”入口。

## 浏览器验收

使用 Playwright CLI 打开 Demo 并重新取快照：

1. 首屏表格显示 6 条测试充值记录，筛选和摘要数字可见。
2. 点击“展开历史”后，历史记录直接插入该主行下方；按钮变为“收起历史”。首次实现曾错误打开详情，已修正并重新验收。
3. 点击 `wang@example.test`，详情显示“付款结果待核实”“等待人工核对”“不可重复充值”和对应 CDK。
4. 桌面截图保存于 `/tmp/orders-structure-v2.png`，列宽、状态层级、双时间和卡台信息可读。
5. `node --check` 对内嵌脚本通过。

## 未验证与边界

- 没有接正式后台 API、生产数据库或真实 CDK。
- 没有把 Demo 作为正式页面实现；后端按 `cdk_id` 归组的查询和历史读取仍待正式任务书与实现验收。
- 移动端仅有响应式 CSS 结构，正式接线前仍需在 375px/390px 真实后台页面复验。
