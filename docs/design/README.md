# 客户充值页设计

## 当前方案：候光（2026-09-11 18:11 UTC 由 Lemon 确认"非常喜欢"，待与后续备选对比后定稿）

**名字的意思**：客户在候，页面有光。这一屏的主角本来就是"时间在流逝"，所以设计的核心是把等待变成有光在动的东西，而不是一个不动的转圈。

- 原型：`prototypes/houguang-v1.html`（可直接用浏览器打开，自动循环播放九个阶段）
- 双主题：**候光·晨雾**（日间，冷绿光晕底 + 纯白卡）／**候光·石板**（夜间，中性冷灰底，不带绿）

### 这版立住的几件事

| 决定 | 为什么 |
|---|---|
| 大进度环当主角，不是卡片上一根细条 | 等待本身是内容。静态版被 Lemon 评为"没什么高级感"，根因是把主角做成了配角 |
| 百分比逐帧线性推进 | 先前按段缓动到位再停住，看着一跳一跳。现在环与数字共用同一个逐帧值，全程匀速 |
| 数字用等宽字体 | 位数变化时不抖 |
| 背后光晕 5.5 秒呼吸一次 | 告诉客户"还在动、没卡死"。盯着不动的页面最容易来找客服 |
| 阶段名淡出淡入、步骤轨逐段亮起 | 硬切会让人怀疑页面刷新了 |
| 尊重系统"减少动态效果" | 开启时全部动画关闭 |

### 九个阶段（客户可见，与内部阶段一一对应）

已收到订单 → 正在准备支付卡 → 正在排队 → 正在验证账号 → 正在获取支付信息 → 正在提交支付 → 正在等待支付结果 → 正在确认订阅 → **订阅成功**

出问题时停在当前那一步，文案换成「遇到点问题，我们已经收到通知在处理」，同一时刻运营手机收到确切原因。

### 文案硬规则

- **不承诺具体秒数。** 允许的说法是「通常几分钟之内完成」；不得写「15 秒到 1 分钟」这类做不到的承诺（真实一单约 2 分 42 秒，且依赖本机执行器在跑）。
- 末步叫「订阅成功」，不叫「充值成功」。

### 设计令牌（取自 Refactoring UI 技能的固定刻度）

- 字号只从 `12 / 14 / 16 / 18 / 20 / 24 / 30 / 36` 选；间距只从 `4 / 8 / 12 / 16 / 24 / 32 / 48` 选
- 颜色写 HSL 不写 hex；灰阶 8–10 档，起点是很深的灰不是纯黑
- 弱化用颜色和字号，**不用更细的字重**（不低于 400）
- 晨雾：灰阶 168°，主色 `hsl(163,72%,26%)`，金 `hsl(38,46%,42%)`
- 石板：灰阶 213°，主色 `hsl(162,58%,49%)`，金 `hsl(38,48%,62%)`

### 踩过的坑（别再犯）

- `.ring svg{transform:rotate(-90deg)}` 是后代选择器，会把环里对勾的 svg 一起转 90 度——对勾因此看着是反的。必须写 `.ring>svg`。
- 按段做 CSS 过渡再停住 ≠ 匀速。要匀速就得逐帧插值。
