# 后台设计规范（收敛中）

立于 2026-09-20，Lemon 定：「我们自己把三套 CSS 收敛成一套规范，并且持续更新优化。」

这份文件是**唯一的样式事实源**。新写的界面只能用这里列的值；要用别的，先改这里。

配套两条机器闸门，别指望自觉：
- `scripts/visual-parity.mjs` —— 页面和已定稿原型的几何量比对（做法见 `VISUAL_PARITY_PROTOCOL.md`）
- `scripts/css-drift-check.mjs` —— 棘轮：硬编码只能减少，不能增加

---

## 一、为什么要收敛（实测现状，2026-09-20）

| | 行数 | `:root` token | 硬编码颜色 |
|---|---|---|---|
| `admin.css` | 298 | 10 | **167 处** |
| `workbench.css` | 272 | 12 | 23 处 |
| `cards.css` | 80 | **0** | 65 处 |

**控件高度散布六种**：44 / 42 / 40 / 36 / 34 / 28 px，没有阶梯。

这不是洁癖问题，当天已经付出过代价：

- **同一个 class 在同一份文件里定义两次**：`.wb-cdk` 先 `align-items:center;gap:8px`，31 行后又
  `align-items:flex-end;gap:10px` 把它盖掉 —— 发码组因此和其余三组不同步，是比对脚本报出来的。
- **同一个尺寸写在两处打架**：数量框宽度 `.wb-num{52px}` 与 `.wb-cdk input.wb-field{72px}`，后者生效。
- **`box-sizing` 只写在 admin.css**：原型少 link 一份，数量框就多出 2px 边框，量出来 30 而非 28。
- **特异性事故**：`.wb-ops .wb-btn{28px}` 被后面的 `.wb-btn{34px}` 盖掉（同级后来者胜），
  只能写成 `.wb-ops .wb-grp .wb-btn` 才生效 —— 层数越堆越深，正是没有规范的症状。

## 二、令牌（唯一来源：`workbench.css` 的 `:root`）

候光·晨雾。**颜色一律走 `var(--wb-*)`，不写字面值。**

| 用途 | token | 值 |
|---|---|---|
| 页面底 | `--wb-bg` | `hsl(168,16%,97%)` |
| 卡面 / 控件底 | `--wb-s` | `hsl(0,0%,100%)` |
| 次级面 | `--wb-s2` `--wb-s3` | `hsl(168,20%,97%)` / `hsl(168,16%,95%)` |
| 描边 | `--wb-bd` | `hsl(168,14%,88%)` |
| 正文 / 次要 / 弱 | `--wb-t` `--wb-t2` `--wb-t3` | 11% / 38% / 50% 明度 |
| 主色 | `--wb-a` `--wb-a-soft` `--wb-a-ink` `--wb-a-on` | `hsl(163,72%,26%)` 等 |
| 语义 | `--wb-ok` `--wb-warn` `--wb-danger` `--wb-info` `--wb-gold` | 各带 `-soft` 变体 |
| 阴影 | `--wb-shadow` `--wb-pop` | — |
| 字体 | `--wb-fd`（正文）`--wb-fm`（数字/等宽） | Familjen Grotesk / IBM Plex Mono |

**语义色和主色是两回事**：好/警告/危险不拿主色代替，主色也不用来表达状态。

## 三、尺寸阶梯

散成六种高度是当前最大的一笔债。新代码只用这三档：

| 档 | 高度 | 圆角 | 字号 | 用在 |
|---|---|---|---|---|
| **紧凑** | `28px` | `7px` | `12.5px` | 工具栏里的控件（营业条全员） |
| **常规** | `34px` | `9px` | `13px` | 页面表单、筛选器 |
| **大** | `44px` | `11px` | `14px` | 移动端触摸目标、主行动按钮 |

嵌套控件比它的容器矮一档的一半：分段器外框 28、里面的按钮 24。

**间距**只用 `4 / 7 / 8 / 10 / 14 / 16 / 22 px`。组内 `gap:10px`，组的内边距 `13px 14px`。

| CDK 流水线页 | `.cdk-page` / `.cdk-kpis` / `.cdk-block` | `step6-cdk-a.html` A（D-313～D-318） | `parity/cdk-page.json`；冻结 `_frozen/cdk-a/` |

CDK 当前沿用 A 的紧凑生成条：桌面主按钮34px；移动控件最小44px、仍9px圆角/13px字号。与上表「大档」的11px/14px不完全一致，已记入本轮验收报告，不扩大范围改其他页面，也不把几何契约通过称为全规范一致。

**互斥的选项用同一种形态表达。** 曾把「当前 API」做成状态、「改用浏览器」做成按钮，
两种形态说同一件事，Lemon 的原话是「视觉和交互有些割裂」——改成分段器后消失。

**一次操作的两半做成连体控件**（`.wb-pair`）：中间不留缝、共享一条边，
而不是两个长得像的独立按钮。

## 五、文案

- **界面上不写解释旁白**（Lemon 说过两次）。`口径待定（D-284 ③）`、`按卡台，聚合待写`
  这类开发备忘不许出现在页面上；内部编号（D-xxx、F-xx）一个都不许。
- 按钮写清楚会发生什么（「生成并复制」而不是「提交」）。
- 没有数据的指标不要摆在显眼处占位 —— 撤下来，等有数据再放。

## 七、怎么防漂移

```bash
node scripts/css-drift-check.mjs          # 硬编码只能减少，不能增加
node scripts/css-drift-check.mjs --update # 降下来之后，把基线钉到新低点
```

基线存在 `docs/design/css-baseline.json`，已接进 `scripts/wrapup-check.sh`。

棘轮只管「不倒退」，管不了「好不好看」——后者归 `VISUAL_PARITY_PROTOCOL.md` 那条链：
定稿原型 → 冻结样式快照 → 契约比几何量 → 变异测试验证闸门本身有效。
