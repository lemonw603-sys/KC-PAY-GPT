客户与付款

这一版把「最低余额」和「每卡单数」从产品表里拎出来，和钱包底线放一起——它们都是挡住一次分配/开卡的门槛，改错了直接影响资金。

§1 · 每一项的真实数据源（都查过，不是照任务书抄的）

  • 水位 / 开卡金额 / 每日上限 → card_supply_policies（按台×按产品）。补卡调度器读的就是它；card_stock_low_threshold 与 card_replenishment_daily_limit 这两个全局键早已被它取代（生产实值 1 与 10，而策略表是 2 与 20），卡片页已于本轮改正。这张表目前没有任何写端点，设置页要新建。
  • 钱包底线 / 告警线 → provider_accounts.wallet_floor / wallet_alert_threshold（按台）。底线就是开卡预检挡开卡的那条线。同样没有写端点。
  • 最低余额 → minimum_required_card_balance:<plan>，写端点已有。
  • 每卡单数 → card_max_successful_payments，写端点已有，但是全局的。
  • Session 门槛 → session_replacement_window_hours（生产 72）。
  • 账单地址 → /api/v1/admin/browser/billing-address，已在诊断页，设置页给入口即可。

§2 · 两处缺口（三版里都标出来了，需要 Lemon 定）

  • 每卡单数不能按产品：D-221 定「Plus 3 单、5X 与 20X 各 1 单」，而现在只有一个全局 card_max_successful_payments=3。要按产品就得新增存储（形如 card_max_successful_payments:<plan>，与最低余额同一套路），并改所有读它的地方（12 处引用）。
  • 5X 最低余额 = $16，而 5X 开卡金额 = $100：只是观察，不下结论——但如果 5X 真按 $16 的门槛分配卡，可能分出一张钱不够的卡。20X 是 150.00 看起来是配过的。5X/20X 目前由 Lemon 人工充、自动化未接入，所以现在不会触发。

§3 · 皮肤

  • 设置页 #settings-view 本来就带 class="view workbench"，在候光作用域里，所以直接用 wb-* 同族样式即可——与 CDK 页那次的坑正好相反（那次是页面不在作用域里却用了作用域内的 class）。
