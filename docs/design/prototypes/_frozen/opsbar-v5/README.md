# 定稿快照：营业条乙-3（2026-09-20）

这三份 CSS 是 `step6-opsbar-v5.html` 定稿那一刻，从 `v1/public/admin/assets/` 原样复制的。
**原型必须 link 这里的快照，不能 link 实时的实现样式。**

## 为什么

2026-09-20 实测踩到的坑：原型本来通过 `scripts/proto-server.mjs` 把 `/admin/assets/*`
反代到跑着的后台，好让原型和实现"同环境"。但这样一来，**改实现的 CSS，原型跟着一起变**——
参照物跟着被测物走，比对永远通过。

当时的变异测试拆穿了它：把 `justify-content` 从 `space-between` 改回 `flex-start`
（就是 Lemon 指出的"挤在左边"），比对脚本仍报"与原型一致"。改 padding 也一样没被抓到。
**没有这一步，我会带着一个永远通过的脚本继续往下走，还以为有保障。**

## 什么时候更新快照

只有在**重新定稿**时：出新原型 → Lemon 挑定 → 才把当时的 CSS 重新冻进来。
日常改实现不更新快照——实现偏离快照正是要被抓出来的东西。
