# 当前工作线｜运营控制面收敛与自动补给

## 项目名称
**AI充值业务｜运营控制面收敛与自动补给**

## 当前阶段
生产 API 核心链路已基本可用；付款前交易证据门槛修复已部署。当前优先完成“自动补余额生产级闭环”。本轮代码审查已修正一个阻断性缺陷：已结算的历史补余额记录不再永久锁住卡片，卡片余额再次降到阈值后可以创建下一次补余额任务。随后完成后台统一营业控制面。

## 已确认事实
- 两笔真实 API 订单分别证明明确失败链路和成功链路。
- 当前生产 release：`/opt/pojia/releases/20260831-preflight-8da5127`。
- Web/Worker active；Browser Worker inactive/disabled；Browser 真实付款未验收。
- 交易证据与卡资料付款前均要求 15 分钟内；订单年龄不受该限制。
- 自动开卡已有订单驱动/日上限规则；自动补余额仍未完成生产写入验收。
- Provider/卡台写权限属于资金控制，不因“开始营业”隐式打开。
- 已结算的补余额尝试是历史记录，不是永久资金栅栏；只有 PREPARED、ACTIVE、UNKNOWN 会阻止同一卡片并发/重复补余额。
- “每卡成功次数上限”必须和跨订单复用同时实现；仅增加配置而保留 `cards.order_id` 单订单绑定没有业务意义。消费账本将作为卡片—订单关联和容量判断的权威来源，第一版采用全局 1–4 次上限。
