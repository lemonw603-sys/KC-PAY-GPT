## 模块核对结果

### 1. 总览与运行控制（C/T/P）

- 总览指标已分为订单处理、资金风险、库存运营、系统健康四组。
- 接单、派发、Worker 心跳、任务租约、Provider 调用停滞、告警和库存指标均有后端来源。
- Provider 写入开关不属于普通数据库设置；生产 readiness 与环境门禁共同确认其关闭状态。
- 生产接单、派发关闭；Web/Worker active；health live/ready 正常。

### 2. 订单查询与详情（C/T）

- 支持订单查询码、CDK、邮箱、ChatGPT 账号 ID、卡号 HMAC、卡台 ID、外部订单号。
- 详情关联订单状态事件、任务、Provider 调用、卡片交易、卡片分配历史、CDK、交付、付款、Session 更换、补发和对账信息。
- 失败订单的 Provider 业务码可在历史字段缺失时只读推导展示；不会修改历史订单主表。

### 3. CDK 管理（C/T）

- 支持 Plus 批次生成、单批次原始 TXT、逐码状态 CSV、作废未使用码、交付记录和补发关系。
- 已增加产品/状态/日期筛选、游标加载更多、批次汇总 CSV 和订单追溯 CSV。
- 明文 CDK 仅在敏感操作接口恢复；安全追溯 CSV 不包含 CDK 明文。

### 4. 卡片库存与卡台路线（C/T/P）

- 库存区分可分配、开卡中、已分配、耗尽、隔离；可分配条件包含卡状态、资料完整和余额达标。
- Provider 账户余额与单卡余额在页面和数据口径上分开。
- 卡台路线支持当前路线展示和人工切换基础能力；当前没有执行路线切换。
- 生产卡片开卡 runner 保持 inactive，卡余额写入门禁关闭。

### 5. 卡片同步与待验证新卡（C/T/P）

- 卡目录同步、卡片只读同步和卡片接管队列均有独立 API/任务。
- 待验证新卡按外部卡 ID 最新记录去重，并排除已进入 cards 的卡。
- 生产只读同步服务正常；本轮没有接管新卡或执行开卡。

### 6. 资金对账与异常队列（C/T/P）

- 对账案例支持列表、筛选、分配、解决和安全 CSV 导出；解决动作只写核对结论，不自动重充或退款。
- 卡余额充值队列支持 PENDING、UNKNOWN、MANUAL_REVIEW、SETTLED、FAILED 展示。
- 生产 readiness：未知 Provider 调用 0、活动资金风险 0、开放对账案例 0。

### 7. Browser 控制面（C/T）

- 页面只展示 run、租约、检查点、付款状态和对账关系，不展示 Checkout authority、Session、卡片凭据或租约令牌。
- Browser 付款未知时进入只对账路径，不能在页面直接重付、换卡或重建 Checkout。
- 现有 Browser 自动化测试通过；未进行真实生产 Browser 付款。

### 8. 通知与运维（C/T/P）

- 开放运营告警由内部提醒显示；Bark 服务 active，死信通知数为 0。
- MySQL、备份 timer、Web、Worker 生产状态正常。
