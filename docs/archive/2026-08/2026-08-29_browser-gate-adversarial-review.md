# Browser 方案对抗式审查（2026-08-29）

## 审查结论

未发现会推翻当前方案的重大资金漏洞。方案保持“最少必要门禁”：一次性 permit、防重复提交、基础订单/卡绑定和结果可追踪；3DS/验证码仅在实际出现时处理。

## 发现并修复的问题

1. **付款前错误被误标为 UNKNOWN**：适配器在提交前发生页面漂移或参数错误时，执行器原先会把订单锁成支付未知，造成不必要的人工对账和流程阻塞。现已将可证明的提交前错误归类为 `PRE_SUBMIT_FAILED`，不写入支付未知。
2. **字段清理并发不稳定**：多个安全字段同时清理在不同页面/iframe 实现上可能留下值。现改为顺序清理，并保留失败时的 DOM 清理兜底。

## 保留的必要限制

- 点击前必须确认唯一可见安全字段和唯一提交控件，防止页面漂移导致误填/误点；这不是业务资格拦截。
- 点击后任何异常或挑战都按 `PAYMENT_RESULT_UNKNOWN` 处理，禁止自动重付、换卡或换执行器。
