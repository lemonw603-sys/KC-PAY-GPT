# Browser Worker 崩溃与数据库重启对抗式审查（2026-08-22）

## 通过项

1. 独立子进程真实持有 MySQL lease，`SIGKILL` 后新 Worker 接管同一 job。
2. 旧 owner/token 的 heartbeat 被 `LEASE_NOT_OWNED` 拒绝。
3. MySQL 容器重启后可重新连接，20 个 claim 全部成功且无重复/残留。
4. 全流程付款动作计数为 0。

## 盲区

### P1：测试容器端口不是稳定输入

容器 restart 后 host 端口从 63168 变成 56392，说明当前测试环境使用动态端口映射。脚本通过 `TEST_DATABASE_URL` 显式输入避免误连，但不能把旧端口写死为长期运行配置。

**整改**：为预发布测试固定端口或在 harness 启动时读取容器端口；报告必须记录实际端口和容器标识。

### P1：未覆盖连接池内部自动重建

本轮是进程/容器重启后新建连接池验证，不是已有 Worker 在连接断开后自动重建连接并继续工作。

**整改**：增加一个持久 Worker 在数据库重启期间收到连接错误、退避重连、重新 claim 的故障注入场景。

### P2：未覆盖页面动作中断

本轮子进程在页面动作前被终止；没有 Browser runtime action 中途失租约或连接中断的实浏览器仿真。

**整改**：沿用 LOCAL_MOCK runtime 的 abort/watchdog 测试，确认动作中断后不调用付款、不重建 job。

## 判定

跨进程租约接管与数据库重启后的控制面恢复通过；连接池自动重建、页面动作中断和长时间 soak 仍未验证，不得外推生产稳定性。
