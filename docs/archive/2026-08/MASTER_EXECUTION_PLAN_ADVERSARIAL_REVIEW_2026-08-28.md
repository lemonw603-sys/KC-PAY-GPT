## 发现并关闭的问题

### 1. “6807 可用”可能被误读为立即可分配

真实订单证明 6807 已成功消费一次，且交易同步存在延迟。因此规划已明确：运营可用不等于当前可分配；消费账本、绑定、余额和交易证据仍必须参与资格判断。

### 2. 人工永久停用可能被 Provider 同步覆盖

现有同步会重写 `inventory_status`。规划已改为最小持久运营策略字段，并要求同步和统一资格查询共同尊重，而不是直接改一次状态。

### 3. 4744 的产品限制可能只停留在 UI

如果资格查询不带产品，Plus 仍可能拿到 4744。规划已要求产品感知资格查询，并禁止尾号硬编码。

### 4. Browser 并行可能绕过库存修复

Browser 不得另建可用卡判断；adapter 必须调用共享资格/资金账本。库存修复未合并前，Browser 只能做非付款联调，不能真实付款。

### 5. “两小时完成项目”不可成为降低闸门的理由

两小时可以完成较大代码和非付款验证批次，但外部页面、真实付款、生产写入、异地恢复和放量验收不能靠时间承诺替代证据。规划没有把这些提前标记完成。
