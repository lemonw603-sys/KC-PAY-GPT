## 接班最该知道的三件

**一、「可分配」显示的是库存口径，别再换成分配口径。** hnskj 的卡**每 3 小时**同步一次，而分配口径要求「15 分钟内同步过」——用它当主数会让好卡在 **91.7% 的时间里显示成 0**。Lemon 2026-09-18 指出过一次，当时只修了补卡调度器，页面这侧漏了半个月。分配口径（`bindableNow`）后端仍在算，但**有意不上界面**（D-312）：它是个会自己恢复的瞬时值，客户下单分不到卡时系统会自动排一次按需同步再重试。**它没有 UI 消费方是有意的，不是 F-71/F-72 那种漏。**

**二、停自动开卡有两条路，都不在那个已删的端点上**：设置页把水位设成 0（按台按产品，只停坏掉那一台）；或 `node v1/scripts/set-supply-scheduler-flag.mjs off --apply`（只写单键、带预览与审计）。

**三、生产现在正有一条 OPEN 的 token 告警**（`provider-token-expired:…0103`，2026-09-18 12:52 起）。上生产后卡片页会立刻显示「已失效」——**那是预期，不是新 bug**。

## 怎么做一页重做（本轮走通的顺序，照搬）

1. 出原型给 Lemon 挑 → 定稿
2. **冻 `_frozen/<页>/` 快照**（三份 CSS + README）
3. **写定稿原型**：link 快照、被量的树里零原型专属 class、**带全外壳**（`.admin-shell` 是 `230px + 1fr`，少了侧栏整页被压窄，本轮因此报出 26 处假差异）
4. **先写契约再实现** —— 第一次跑必然红，这本身就证明它不是空的
5. 实现到绿
6. **变异测试**：故意改坏看契约报不报。抓不到的要么补探针，要么**如实标明盲区**

## 禁止 / 注意

- 开卡 / 补余额 / 充值 / 付款 / 退款 / 切路线 / **发布 / 应用迁移** / 改开关 / 重启常驻 worker **先开口问**；不碰 browser-mvp（D-254）。
- **发布门槛三件**：外观符合选定方案 + 数据字段口径正确 + 按钮业务结果正确。测试数量 / HTTP 200 / SQL 有返回**都不算数**。
- **CSS 只许降不许升**（D-293）：新规则用裸 `var(--wb-*)`，不加字面色回退。
- **界面「像不像设计稿」不许用眼睛判**（D-292）：测量前先断言 `innerWidth`；放大只用 `transform: scale()`。
- **删代码按语法边界（配对大括号），不按字符串距离**（D-289）。本轮又犯了一次：删一个函数时切到 `return {` 为止，把夹在中间的 `closeAlert`（工作台「关闭告警」在用）一起删了，`node --check` 过、5 条测试红了才发现。
- **说「不存在 / 零引用」之前至少查三种形态**。本轮两次靠它避坑（`DELETE /card-operational-overrides` 早就有、token 告警 key 有第二种形态），也因只查一种而翻车一次（删孤儿常量只 grep 了名字、没查内容，而有测试按内容撞它）。
- **演示库造数偏离生产时，它既会假装成 bug，也会掩盖 bug**。本轮被误导三次（5X 门槛、chargeback 符号、快照时间），都已对齐生产。
- **「两处一致」不等于「两处正确」**（D-307 的教训）。
- **「有意留红」的测试必须定期确认它红的是不是那个原因**（F-65 红了半个月，红的是个过期的版本号）。
- **界面上每多一句话，先问它对着的人能不能据此做点什么**（D-312 的教训）。
