# 任务书｜导航失败证据包（D-379，待 Lemon 批）

## 目标

导航这一步失败时，自动留下一份**能看出原因的现场**，下次不用拿真单一遍遍试、也不用靠猜。
起因：2026-09-25 块 6 演练三次导航失败，只有一行报错；「付款表单加载失败」到现在原因未知（D-378）。

## 范围（第一期）

- **只管「导航到结账页」这一步的失败**（`CHECKOUT_NAVIGATION_FAILED`：找不到按钮、按钮一直灰、等结账页超时、租约过期等）。今晚三次失败都在这一步。
- 这一步在填卡之前：页面上还没有卡号。结账页观察、填卡、付款段**不录**（以后要扩，单独批）。
- 生产常驻池与演练都走同一段代码，所以两边都会存（见「要 Lemon 定」第 1 条）。

## 每次失败留什么

放在本机 `~/Library/Application Support/pojia-browser-live/evidence/<UTC 时间>-<运行短号>/`（目录 700、文件 600，不上传、不进 git）：

| 文件 | 内容 |
|---|---|
| `summary.json` | 原因码、清洗后的报错首行、已走步骤、各文件大小 |
| `steps.json` | 导航每一步：步骤名、UTC 时间、网址（只留域名+路径，长串编号替换）、当时关键按钮可不可点 |
| `console.json` | 页面控制台的错误和警告（Playwright 保留的最近 200 条内），文字清洗 |
| `page-errors.json` | 页面脚本报错，文字清洗 |
| `network.json` | 请求清单：方法、域名+路径、状态码、失败原因、耗时。**不记请求头、Cookie、请求体、响应体** |
| `page.aria.txt` | 页面结构的文字版（看得出当时有哪些按钮、哪个栏选中、页面上写了什么错），邮箱替换 |
| `screenshot.png` | 失败那一刻的截图（仅本机） |

**绝不记录**：Cookie、Authorization 及任何请求头；请求/响应内容；session token；卡号、CVV（这一步页面上本来没有；另加检查：页面上若已出现填过的卡号框就不截图、不存页面结构）；文字里的邮箱替换成 `<email>`，长串 token/数字串替换。
**不用 Playwright trace**：trace 会录请求头（含登录 Cookie），存下来就违反「日志不得出现 sessionToken」。

## 边界

- 证据存不成（磁盘满、目录不可写、页面已关）**不能改变订单结局**：照原样安全停下，只在失败事件里多记一句「证据未存成」。
- 取证最多花 5 秒，不延长租约、不在页面上点任何东西（只读）。
- 每份不超过 5 MB（超了先丢截图）；保留 14 天，写新证据时顺手删旧的。
- 数据库失败事件只多一个字段：证据目录名（不含内容），从订单能找到对应文件夹。
- 做在 `block6-pro5x` 分支（对照实验要用块 6 代码），随块 6 一起合并发布。

## 验收（动手前定，做完逐条走）

1. 本地假页面造三种导航失败（找不到按钮、按钮一直灰、等结账页超时），每种都生成齐全的证据目录。
2. **泄密检查**：假页面里埋假 Cookie、假 session token、假 Authorization 头、假邮箱、16 位数字串，证据目录全文搜索一个都搜不到（自动测试）。
3. 证据写不成时，订单结局与现在完全一样（测试）。
4. 5 MB 上限、14 天清理（测试）。
5. 变异验证：去掉清洗 / 去掉写入 / 去掉卡号框检查，各至少一条测试变红。
6. browser-mvp 全量测试全绿。
7. 第一次真用 = 对照实验（不付款、测试号、3 号窗口）：我打开证据目录，把看到的东西讲给 Lemon 听（「我看到了什么」，不是「做好了」）。
