# 任务书｜导航失败证据包（D-379；D-380 Lemon 放开存储限制后开工）

## 目标

导航这一步失败时，自动留下一份**能看出原因的现场**，下次不用拿真单一遍遍试、也不用靠猜。
起因：2026-09-25 块 6 演练三次导航失败，只有一行报错；「付款表单加载失败」到现在原因未知（D-378）。

## 范围（第一期）

- **只管「导航到结账页」这一步的失败**（`CHECKOUT_NAVIGATION_FAILED`：找不到按钮、按钮一直灰、等结账页超时、租约过期等）。今晚三次失败都在这一步。
- 这一步在填卡之前：页面上还没有卡号。结账页观察、填卡、付款段**不录**（以后要扩，单独批）。
- 生产常驻池与演练都走同一段代码，所以两边都会存（见「要 Lemon 定」第 1 条）。

## 每次失败留什么（D-380：不限制存什么）

放在本机 `~/Library/Application Support/pojia-browser-live/evidence/<UTC 时间>-<运行短号>/`（目录 700、文件 600，不进 git、不上传）：

| 文件 | 内容 |
|---|---|
| `trace.zip` | **Playwright 完整录制**：每个动作的时间线、前后页面快照、截图、网络请求（含请求头、Cookie、返回内容）、控制台。用 `npx playwright show-trace trace.zip` 打开 |
| `summary.json` | 原因码、报错首行、已走步骤、各文件大小、取证中哪些步骤没成功 |
| `console.json` / `page-errors.json` | 页面控制台消息与脚本报错（原文） |
| `network.json` | 请求清单（方法、网址、状态码、失败原因）；出错的请求附返回内容前 8 KB，方便不开 trace 先看一眼 |
| `page.aria.txt` / `page.html` / `screenshot.png` | 失败那一刻的页面结构、完整 HTML、截图 |

- 已验证（2026-09-25，本地临时浏览器）：接管已打开浏览器（connectOverCDP）时 trace 能录，请求头（含 Authorization）与服务器返回内容都在 trace 里。
- **只留一条线：卡号 / CVV 不进证据**。做法是结构性的：录制只从「开始导航」录到「进结账页」为止，导航成功就停止并丢弃录制，填卡永远在录制之外——不需要额外过滤。
- 证据里会有登录 Cookie / token、邮箱等：只在本机、700 权限、14 天自动删；不贴进聊天或上传；AI 查证据时优先看报错与状态码，不去读请求头。
- 每份上限 100 MB（超了先丢截图与 HTML，再丢 trace，summary 里写明）。

## 边界

- 证据存不成（磁盘满、目录不可写、页面已关、录制已被占用）**不能改变订单结局**：照原样安全停下，失败事件里记 `evidenceRef: null` 与原因。
- 取证总共最多 15 秒，只读、不点页面。
- 数据库失败事件只多一个字段 `evidenceRef`（证据目录名，不含内容），从订单能找到对应文件夹。
- 生产常驻池与演练都开（D-380）；环境变量 `BROWSER_NAVIGATION_EVIDENCE=off` 可关。
- 做在 `block6-pro5x` 分支（对照实验要用块 6 代码），随块 6 一起合并发布。

## 验收（动手前定，做完逐条走）

1. 本地假页面造三种导航失败（找不到按钮、按钮一直灰、等结账页超时），每种都生成齐全的证据目录，trace 能打开。
2. 导航成功时：录制停止并丢弃，不留任何文件；之后的动作（填卡段）不在任何录制里（测试）。
3. 证据写不成 / 录制已被占用时，订单结局与现在完全一样（测试）。
4. 100 MB 上限、14 天清理、700/600 权限（测试）。
5. 变异验证：去掉取证调用 / 去掉成功时丢弃 / 去掉清理，各至少一条测试变红。
6. browser-mvp 全量测试全绿。
7. 第一次真用 = 对照实验（不付款、测试号、3 号窗口）：我打开证据，把看到的东西讲给 Lemon 听。
