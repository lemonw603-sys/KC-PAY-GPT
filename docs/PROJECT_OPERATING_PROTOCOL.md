# 项目协作与交付协议

本协议把“事实、决策、规划、执行、验收、交接”固定成可重复流程。

## 一、唯一入口

每次开始工作先读取：

1. `docs/SINGLE_SOURCE_OF_TRUTH_2026-08-21.md`
2. `docs/DECISIONS.md`
3. `docs/EVIDENCE_MATRIX_2026-08-23.md`
4. `progress.md`
5. 当前阶段对应的路线图/验收文档

## 二、任务卡格式

```text
任务：
所属阶段：
目标：
范围：
证据要求：
禁止操作：
是否允许生产写入：是/否
完成标准：
```

## 三、证据等级

- `P`: 生产运行、生产日志或生产数据库证据
- `D`: 只读数据库/网络证据
- `C`: 代码证据
- `T`: 自动化/隔离测试证据
- `H`: 历史聊天证据
- `U`: 未核验

报告中不得只写“已验证”，必须写等级，例如：`代码和隔离测试已验证（C/T），生产未验证（U）`。

## 四、执行闸门

- 只读检查：可直接执行。
- 可回滚代码/文档/禁用服务：执行前说明，完成后验证。
- Provider 写入、开卡、卡充值、客户充值、提现、退款、删除业务数据：必须单独获得明确确认。

## 五、阶段闭环

每个阶段必须完成：

1. 对照路线图确认没有跑偏；
2. 实施最小变更；
3. 本地测试；
4. 生产只读/运行验证；
5. 对抗式审查；
6. 更新单一事实源、证据矩阵、决策账本和 `progress.md`；
7. 写明未完成项和下一阶段入口条件。

## 六、固定汇报格式

```text
结论：
已完成（证据等级）：
未完成：
发现的偏差：
风险：
下一步：
需要确认的动作：
```

## 七、暂停/恢复记录

```text
暂停原因：
暂停范围：
允许继续：
禁止操作：
恢复条件：
恢复后的第一步：
```

## 八、完成定义

只有同时满足以下条件才可标记“阶段完成”：代码、测试、部署、生产验证、文档、对抗式审查、回滚路径全部具备。否则必须标记为“部分完成”。
