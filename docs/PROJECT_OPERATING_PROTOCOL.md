# 项目协作与交付协议

本协议把“事实、决策、规划、执行、验收、交接”固定成可重复流程。

## 一、唯一入口

每次开始工作先读取：

1. `docs/SINGLE_SOURCE_OF_TRUTH_2026-08-21.md`
2. `docs/DECISIONS.md`
3. `docs/EVIDENCE_MATRIX_2026-08-23.md`
4. `progress.md`
5. 当前阶段对应的路线图/验收文档

## 二、任务卡格式

```text
任务：
所属阶段：
目标：
范围：
证据要求：
禁止操作：
是否允许生产写入：是/否
完成标准：
```

## 三、证据等级

- `P`: 生产运行、生产日志或生产数据库证据
- `D`: 只读数据库/网络证据
- `C`: 代码证据
- `T`: 自动化/隔离测试证据
- `H`: 历史聊天证据
- `U`: 未核验

报告中不得只写“已验证”，必须写等级，例如：`代码和隔离测试已验证（C/T），生产未验证（U）`。

## 四、执行闸门

- 只读检查：可直接执行。
- 可回滚代码/文档/禁用服务：执行前说明，完成后验证。
- Provider 写入、开卡、卡充值、客户充值、提现、退款、删除业务数据：必须单独获得明确确认。

## 五、阶段闭环

每个阶段必须完成：

1. 对照路线图确认没有跑偏；
2. 实施最小变更；
3. 本地测试；
4. 生产只读/运行验证；
5. 对抗式审查；
6. 更新单一事实源、证据矩阵、决策账本和 `progress.md`；
7. 写明未完成项和下一阶段入口条件。

## 六、固定汇报格式

```text
结论：
已完成（证据等级）：
未完成：
发现的偏差：
风险：
下一步：
需要确认的动作：
```

## 七、暂停/恢复记录

```text
暂停原因：
暂停范围：
允许继续：
禁止操作：
恢复条件：
恢复后的第一步：
```

## 八、完成定义

只有同时满足以下条件才可标记“阶段完成”：代码、测试、部署、生产验证、文档、对抗式审查、回滚路径全部具备。否则必须标记为“部分完成”。

## 错误处理原则

发现问题后必须优先修正事实源、实现或流程本身；不能只新增一条“发现问题”记录就结束。修正后再记录：修正内容、验证证据、剩余未验证边界和回滚点。历史记录只有在需要保留时间线时保留，并明确标注已被修正/覆盖，不能继续作为当前依据。
# 协作节奏补充（2026-08-30）

- 用户明确要求：执行阶段不要把工作拆成过细步骤反复请求确认；应合并推进较大工作块，仅在确实需要用户决定、授权或提供输入时暂停确认。
- 该节奏要求适用于本项目及其并行窗口；执行结果仍须验证并落盘。

## 九、就绪声明强制闸门（2026-09-05）

任何输出“可以开始”“已准备好”“已跑通”“已完成”的结论前，必须先生成本轮证据快照，逐项填入：

```text
目标动作：
当前生产 release/commit：
代码/测试证据：
生产服务状态：
数据库/订单实际状态：
执行器目标（真实/fixture）：
路线与权限开关：
本轮是否出现真实任务/运行记录：
仍未验证：
```

规则：

1. 没有本轮证据快照，不得使用完成式或就绪式措辞；历史对话只能作为线索（H），不能替代 C/T/D/P 证据。
2. “代码通过”“本地预检通过”“生产可执行”“付款已验收”必须分开报告，不得合并成一个结论。
3. 客户提交后必须立即核对订单冻结路线和对应执行任务；未核对前不得让客户重复提交或继续下一阶段。
4. 方案写入文档不等于机制已执行；若没有脚本、代码门禁或现场命令证据，只能标记为“规划”。
5. 发现一次同类偏差后，必须同时修复事实源、执行流程和报告模板，并用一次反例回归验证，不能只写复盘文字。
