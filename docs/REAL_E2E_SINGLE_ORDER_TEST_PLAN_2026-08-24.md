# 单笔真实全链路测试计划与证据表（2026-08-24）

> 状态：准备中，尚未执行任何真实开卡、卡余额充值或 Plus 充值写入。  
> 范围：生产 **API 执行器** 单笔、并发 1 的正式订单库链路。Browser 真实付款尚未达到生产闸门，不纳入本单付款执行，但检查其共享数据边界。  
> 原则：一个订单、一个 CDK、一个免费 ChatGPT 账号；不重复点击，不换幂等键；任何 UNKNOWN、余额差异或状态冲突立即停单并对账。

## 一、本次要证明的闭环

```text
后台生成 Plus CDK
→ 客户在 plus.vibebridge.top 提交 CDK + 完整 Session
→ 建立订单并冻结执行路线
→ 分配符合资格的 active 未使用卡
→（卡余额不足时）通过卡台 API 给该卡补余额
→ API 执行器提交 Plus 购买一次
→ 轮询 Provider 最终结果
→ 取消自动续费并核验取消状态
→ 订单最终成功
→ CDK/邮箱/订单/卡号/Provider 订单/卡片交易/金额/时间可双向追溯
→ 前后余额和交易对账
→ 无遗留 Permit、UNKNOWN、资金风险或过期租约
```

若卡台库存没有合格卡，允许本单覆盖：自动/人工开一张卡、补充卡余额、接管和分配。但每个资金写动作只能执行一次，并使用持久化幂等键。

## 二、开始前硬闸门

以下全部满足才允许开放这一单：

- [ ] 卡台升级已结束，HNSKJ 只读检查成功；
- [ ] 目标 ChatGPT 账号当前为免费账号；不单独调用额外账号预检，使用正式充值调用返回判定；
- [ ] 使用完整、未过期 Session；敏感 Session 只在客户页面提交，不进入聊天、普通日志或报告；
- [ ] 生产 release、数据库迁移和配置与当前代码要求一致；
- [ ] `expired_task_leases=0`；
- [ ] `uncertain_provider_calls=0`；
- [ ] `active_or_unknown_funds_risk=0`；
- [ ] 活动充值 Permit 为 0；
- [ ] 无未解释的余额差异或开放高风险对账案件；
- [ ] Web、Worker、只读同步、Bark 正常；
- [ ] 记录执行前卡台账户余额、目标卡余额、可分配库存和 Provider 余额；
- [ ] 接单/派发/Provider 写开关只在单笔窗口内按最小范围开启；
- [ ] 并发固定为 1，自动补卡日上限及当日用量核对无误。

任一项失败：不开始资金写入，保存证据并修复。

## 三、分阶段执行与验收

### A. 无资金预检

1. 生产 readiness；
2. HNSKJ/旧 API 执行器只读连接检查；
3. 后台检查接单、派发、Provider/卡台写入、当前卡台；
4. 核对库存、卡台账户余额、卡目录同步时间；
5. 核对无活动任务、Permit、UNKNOWN 和资金风险；
6. 记录 release、迁移版本、服务/定时器状态。

### B. CDK 和客户入口

1. 后台生成一枚 Plus CDK，记录批次、生成时间和状态；
2. 检查 CDK 可查询、可作废但本单不作废；
3. 临时开启接单；客户提交 CDK + Session 后立即关闭新接单；
4. 核对 CDK 仅消费一次，重复提交不能创建第二单；
5. 核对客户页面无附加文本导致的 Session 格式问题；
6. 核对订单号、邮箱、产品、创建时间和 CDK 关系。

### C. 卡片与资金准备

1. 只允许选择 `active + 未绑定订单 + 无客户 PURCHASE + 资料完整 + 无资金争议` 的卡；
2. 默认不复用已消费/已绑定卡；特殊复用不在本次自动流程中；
3. 若无卡：订单进入 `WAITING_FOR_CARD`，后台和 Bark 可见；
4. 若触发开卡：只开 1 张，核对 `$16`、当日自动额度和幂等键；
5. 若卡余额不足：只发起一次卡余额充值并核对 `card_funding_attempts`；
6. `PENDING/UNKNOWN` 时不更换幂等键、不重复充值，进入人工对账；
7. 记录目标卡后四位；完整卡号仅在受控后台详情核对。

### D. Plus 购买和取消续费

1. 临时开放本单派发和必要 Provider 写入；
2. 仅该订单获得一次性资金许可/资金栅栏；
3. Provider 创建调用最多一次；
4. Plus 账号、Session 无效等正式调用错误应映射为客户可修复状态，不显示“卡片不足”；
5. Session 可在原订单 72 小时内最多更换 3 次；
6. 明确成功后继续取消自动续费；
7. 只有 `is_subscription_cancelled=1` 才进入最终成功；
8. 未确认取消时进入等待/人工复核，不能虚报成功；
9. 完成后关闭接单、派发和所有资金写开关。

### E. 全链路对账与追溯

后台分别用以下入口反查并交叉核对：

- CDK；
- 客户邮箱；
- 订单号；
- 充值时间范围；
- 卡号/后四位；
- Provider 外部订单号。

每个入口应能回到同一链路：

- CDK 与批次；
- 本地订单；
- 产品 Plus；
- 邮箱与时间；
- Session 更换次数（不展示 Session 明文）；
- 卡片和分配历史；
- Provider 路线与外部订单；
- 卡余额充值金额；
- Plus 充值金额；
- 卡片交易；
- 最终状态；
- 自动续费取消状态；
- 失败/人工处理/对账案件（如有）。

资金核对：执行前后卡台账户余额、目标卡余额、卡片交易、Provider 结果和本地账本必须能够解释且一致。

### F. 客户与后台体验检查

- 客户页面：提交、处理中、需要更换 Session、等待、成功/失败提示清楚；
- 客户问题与内部问题分离；
- 后台刷新后状态不丢失；
- 总览、订单、库存、CDK、资金与对账的数据口径一致；
- Bark 不包含完整 CDK、Session、PAN、CVV、API Key；
- 页面布局、下拉箭头、文字溢出和移动/桌面布局同步观察。

## 四、立即停止条件

- 重复订单、重复开卡、重复卡余额充值或重复 Plus 创建；
- Provider/卡台返回 UNKNOWN 或无法确认；
- 余额、流水、本地账本无法解释；
- 卡台升级后 Schema/状态含义发生漂移；
- Worker 租约异常、连续 5xx/429、Bark DEAD；
- 客户、后台、本地数据库与外部权威状态冲突；
- 目标账号不是免费账号；
- 取消自动续费无法确认。

停止后：关闭新接单和新派发，但继续追踪已有订单；不自动换卡、换执行器、重充或退款。
