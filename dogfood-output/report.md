## 问题

### 1. 批量生成 CDK 后没有按页面承诺自动导出

- 严重度：High
- 分类：Functional / UX
- 状态：已修复，待生产验收
- 证据：页面写“生成后会自动下载 TXT”，成功分支只显示隐藏结果区，没有调用下载函数。
- 修复：按钮改为“生成并导出整批 TXT”，生成成功后把该批次全部 CDK 合并为一个 TXT 自动导出；当前批次和历史批次均提供明确的整批再次导出入口。

### 2. 所选卡段规则被塞入窄列导致强制乱行

- 严重度：Medium
- 分类：Visual / UX
- 状态：已修复，待生产验收
- 证据：生产页面中规则卡宽约 170px，而表单宽约 529px；卡段名称、ID、BIN 和金额范围挤在同一文本块。
- 修复：表单改为两列，规则卡独占整行并拆成“卡段名称 / ID 与 BIN / 允许金额”三个稳定字段；手机宽度改为单列。

### 3. 卡片类型下拉过宽，原生箭头离内容太远

- 严重度：Medium
- 分类：Visual / UX
- 状态：已修复，待生产验收
- 修复：桌面端下拉最大宽度收敛到 310px并左对齐；手机端仍使用整行宽度。

### 4. 金额以六位小数显示，影响运营扫读

- 严重度：Low
- 分类：Content / Visual
- 状态：已修复，待生产验收
- 证据：生产页面显示 `$35.710000`、`$16.000000`。
- 修复：后台展示统一为两位小数，数据库精度不变。

### 5. CDK 页面仍写“SHA-256”，与当前 HMAC 实现不一致

- 严重度：Low
- 分类：Content
- 状态：已修复，待生产验收
- 修复：说明改为“数据库仅保存不可逆 HMAC，批次恢复副本加密保存”。

### 6. 数据库备份与恢复密钥都在同一台服务器

- 严重度：High
- 分类：Resilience
- 状态：未完成，需要用户指定异地保存位置
- 证据：生产有 17 份已加密备份且恢复演练通过，但备份文件与 `/etc/pojia` 密钥同机保存；备份基线也明确将异地副本标记为未完成。
- 风险：整机丢失时，订单、CDK 恢复副本和加密 Session 无法恢复。
- 必须动作：建立一份异地加密数据库副本，并把恢复所需密钥做一次离线托管；两者分开保存。

### 7. 后台没有 Worker 心跳和外部异常通知

- 严重度：Medium
- 分类：Operations / UX
- 状态：未完成；首批人工盯盘可接受，持续放量前必须完成
- 证据：Web/Worker 由 systemd 自动重启，任务可租约恢复，卡台快照过期会禁止开卡；但后台不能直接判断 Worker 是否失联，Telegram 通知仍在路线图待办。
- 建议：后台增加 Worker 最近心跳、过期任务数和关键定时器状态；外部通知只发送异常摘要，不发送卡号、Session 或 CDK。

### 8. 退款候选可以发现，但人工确认与提取闭环尚未完成

- 严重度：Medium
- 分类：Functional / Operations
- 状态：延期到首批 3–5 单后、10–20 单前
- 证据：交易同步、疑似退款候选和内部提醒已存在；人工确认和人工提取页面仍在路线图待办。
- 边界：首批订单逐单监督时可在卡台人工处理；持续运营前不能继续依赖临时人工记录。
